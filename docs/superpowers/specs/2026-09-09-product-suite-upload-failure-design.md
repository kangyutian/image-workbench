# 商品套图上传限制与失败状态设计

## 目标

避免商品套图任务因 WaveSpeedAI 的图片大小限制在后台才失败，并让主任务失败时四个子任务显示真实失败状态，而不是继续显示“等待共享执行槽位”。

## 现状与根因

- 前端 `readImages` 直接把原始文件读取为 data URL，商品套图上传流程只限制图片数量，没有在选择时检查文件大小，也没有压缩。
- 服务端 WaveSpeedAI 图片上传严格要求文件大小小于 `10 * 1024 * 1024` 字节。套图主流程在 `product-reference-upload` 阶段并行上传商品参考图，其中任意一张超限都会使整个阶段失败。
- `executeProductSuiteTask` 的顶层 `catch` 只更新套图记录和父任务记录，没有更新仍处于 `queued` 的套图子项，因此界面会同时显示主任务失败和子项等待执行槽位。

## 设计

### 前端图片处理

商品套图选择商品图片时保留原始文件的正常路径。只有文件大小达到或超过 WaveSpeedAI 限制时，才在浏览器中使用 Canvas 重新编码：

1. 保持图片的视觉尺寸和比例；必要时逐步缩小尺寸。
2. 对有透明通道的图片使用 WebP/PNG 兼容输出，对普通图片使用高质量 JPEG/WebP。
3. 迭代降低质量或尺寸，直到输出严格小于 10MB，并以约 8MB 作为目标缓冲。
4. 如果浏览器无法产生合格结果，阻止加入套图图片并显示明确的压缩失败提示。
5. 压缩后的 `dataUrl`、`mimeType` 和 `size` 一起写入套图图片状态，提交接口无需改变。

前端提示应明确说明限制是“必须小于 10MB”，避免用户上传刚好 10MB 的文件。

### 服务端失败状态

在套图主流程的顶层失败处理处，保留现有主任务错误信息，并遍历该套图当前的 `items`：

- 只把 `queued` 子项改为 `error`。
- 子项错误信息使用主流程错误信息，例如“图片超过 WaveSpeedAI 的 10MB 限制，请压缩后再试。”。
- 已完成、已失败或正在运行的子项不被覆盖。
- 该逻辑覆盖上传、抠图、背景上传、模型参考图上传等尚未进入全部子项生成的失败阶段。

## 测试策略

- 新增前端图片压缩/大小处理的纯逻辑测试，覆盖低于限制原样保留、超限后压缩、压缩仍失败时拒绝，以及严格小于 10MB 的边界。
- 新增套图失败状态测试，验证顶层失败会把排队子项置为 `error`，同时保留已完成和已失败子项。
- 保留现有套图模型、上传、调度器和全量测试。
- 完成后运行套图相关测试、全量 `npm.cmd test`、生产构建、`node --check server.mjs` 和 `git diff --check`。

## 非目标

- 不改变 WaveSpeedAI 的 10MB 限制。
- 不修改 WaveSpeedAI API Key、服务器 `.env` 或线上数据。
- 不改变套图提示词、模型选择、生成顺序或并发数。
- 不自动重新提交已经失败的线上任务。
