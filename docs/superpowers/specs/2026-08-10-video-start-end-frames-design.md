# 视频首尾帧上传设计

## 目标

在现有视频创作界面中支持第二张可选图片：第一张作为首帧，第二张作为尾帧。只上传一张图片时保持当前行为，继续生成单首帧视频。

## 支持范围

- Seedance 2.0 Mini、Seedance 2.0、Seedance 2.0 Fast：首帧映射为 `image`，可选尾帧映射为 `last_image`。
- Kling 3.0 Standard、Kling 3.0 Pro：首帧映射为 `image`，可选尾帧映射为 `end_image`。
- Grok Imagine Video v1.5：API 仅支持单张 `image`，界面不显示尾帧槽位。
- Kling 3.0 Standard motion-control：继续使用单张人物图片和一段动作视频，界面不显示尾帧槽位。
- 本次不实现 Seedance reference-to-video，也不允许上传三张及以上图片。

## 界面行为

- 将当前单个“参考图片”区域改为两个有顺序的槽位：
  - “首帧图片（必填）”
  - “尾帧图片（可选）”
- 只有模型声明支持尾帧时才显示第二个槽位。
- 每个槽位可独立选择、预览、替换和删除。
- 从图片任务结果点击“用于生成视频”时，该图片进入首帧槽位，不影响尾帧。
- 切换到不支持尾帧的模型时，清除客户端尾帧状态，避免不可见数据被提交。
- 生成按钮在首帧缺失时保持现有校验；尾帧缺失不报错。

## 数据与接口

- 客户端继续使用有序的 `referenceImages` 数组：索引 0 是首帧，索引 1 是尾帧。
- 上传时首帧和尾帧并行上传；任一上传失败则不创建任务，并显示明确错误。
- 服务端按模型限制图片数量：
  - 支持尾帧的模型：1–2 张。
  - 不支持尾帧的模型：恰好 1 张。
- 服务端 payload 只发送模型支持的字段，不发送空尾帧字段。
- 任务重试沿用原任务的 `referenceImages` 顺序。
- 现有单图任务和历史任务无需迁移。

## 错误处理

- 没有首帧：提示“请先上传首帧图片”。
- 支持尾帧的模型上传超过两张：服务端返回 400。
- 单图模型收到第二张图：服务端返回 400，不能静默丢弃。
- 图片上传失败：保留本地已选图片，允许用户重试。

## 测试与验收

- 服务端模型测试覆盖 Seedance 的 `last_image`、Kling 的 `end_image`、单图 payload 不含尾帧字段。
- 验证 Grok 和 motion-control 拒绝第二张图。
- 前端构建通过，单图和双图任务均可序列化。
- 完整测试套件和生产构建通过后再部署。
- 部署后验证首页可访问、服务 active、未登录管理员接口仍返回 401，并以测试账号执行单图与双图视频任务 smoke test（若不消耗真实额度，则至少验证创建任务与请求 payload）。

## 非目标

- 任意多参考图、参考视频或参考音频。
- 新增 Seedance reference-to-video 或 Grok reference-to-video 模型。
- 改动现有计费统计、账号权限或图片任务流程。
